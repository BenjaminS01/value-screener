# Don't Trust the LLM: Citation Cross-Checking (Guardrail B)

**Where this comes from:** Task 4 — the core of `CompanyResearchAgent`.

**Level:** mid-level. Assumes you've called an LLM API before; this is about a verification pattern
for *any* system where an LLM's claims feed into something consequential.

## The problem: LLMs can state false things confidently, including about their own sources

`CompanyResearchAgent` asks Claude to research a company using a web-search tool, and to cite sources
for its claims. The naive design would be: trust whatever URLs the model says it used, show them to
the user as "sources," done. The problem is that an LLM's final text answer and the *tool calls it
actually made* are two separate things that can diverge — the model can state in its prose "according
to [some URL]..." without that URL ever having actually been returned by a real search, especially
under the pressure of producing a complete-looking answer. Trusting the model's self-reported sources
means trusting it to accurately report its own tool-call history inside free-form text — an
unnecessary and unverified assumption when better data is available.

## The available ground truth: real citation metadata

When Anthropic's hosted web-search tool is used, the API response includes structured citation
metadata separate from the model's prose — actual `Citation` objects (in Spring AI's mapping:
`org.springframework.ai.anthropic.Citation`, with a real `getUrl()`) reflecting what the tool
*actually* returned, retrieved via `response.getMetadata().get("citations")`. This is qualitatively
different from the model's own prose claims: it's populated by the underlying search mechanism
itself, not generated by the language model's next-token prediction.

## The cross-check, concretely

`CompanyResearchAgent.research(...)` does roughly this (simplified):

```java
ChatResponse response = chatModel.call(prompt);
RawResearchResponse raw = objectMapper.readValue(response.getResult().getOutput().getText(), RawResearchResponse.class);

List<String> actuallyCitedUrls = extractCitedUrls(response); // reads response.getMetadata().get("citations")

List<SourceReference> verifiedSources = raw.sources().stream()
    .filter(source -> actuallyCitedUrls.contains(source.url()))
    .map(source -> new SourceReference(source.url(), source.claim()))
    .toList();

ConfidenceLevel confidence = (raw.noReliableReportFound() || verifiedSources.isEmpty())
    ? ConfidenceLevel.LOW
    : ConfidenceLevel.HIGH;
```

Every source the model *claims* to have used gets checked against the set of URLs the search tool
*actually* returned. A claimed source that isn't in that real set gets silently dropped — not shown
to the user as a citation, because it can't be verified to be real. If **no** sources survive this
check, or if the model itself flagged `noReliableReportFound`, the result is forced to
`ConfidenceLevel.LOW` regardless of how confident the model's prose sounded. Confidence, in other
words, is not something the model gets to self-report unchecked — it's *derived* from a verifiable
fact (did any claimed source actually correspond to a real tool call?), and downgraded whenever the
underlying evidence doesn't hold up.

## Why "drop the source" and not "reject the whole answer"

A tempting alternative design would be: if any claimed source can't be verified, discard the entire
research result as untrustworthy. This project deliberately does something more surgical: drop only
the unverifiable *source*, keep the rest of the answer, and let the confidence level (not an
all-or-nothing accept/reject) communicate the trust level to whatever consumes this result. This
matches how a careful human researcher would actually work — if one citation in a report turns out to
be wrong, you don't throw out the whole report, you note that the shaky claim is now unsupported and
adjust your confidence in it specifically.

## The general pattern, beyond this specific app

This is an instance of a broader principle worth generalizing: **whenever an LLM's free-form output
makes a factual claim that a *separate, structured, verifiable* signal could check, check it — don't
rely on the model's own narrative self-report.** Other places this same pattern shows up in
LLM-integrated systems you might build later:

- A model claims "I called function X and it returned Y" — verify against your actual function-call
  log, don't trust the prose summary.
- A model claims a document contains a specific fact — if you have the actual document text
  available, grep for the claim rather than trusting the model read it correctly.
- A model reports "the test passed" inside an agentic coding loop — verify by actually running the
  test, never trust the model's narrated summary of what it did (this exact principle is why this
  project's own SDD process required literal `mvn test` output as evidence for every task, not a
  subagent's description of having run it).

## Takeaways for your own code

1. When an LLM call produces both free-form text *and* structured metadata about what actually
   happened (tool calls, citations, function results), treat the structured metadata as ground truth
   and the free-form text as an unverified claim about that ground truth — even though both came from
   the same response.
2. Downgrade confidence based on verification failures rather than either blindly trusting the model
   or discarding the whole answer on any single unverifiable claim.
3. This pattern generalizes far beyond citations — anywhere an LLM narrates what it did, and you also
   have an independent record of what it actually did, cross-check rather than trust the narration.
